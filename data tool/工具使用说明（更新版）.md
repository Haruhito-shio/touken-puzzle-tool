## 一、这个工具是干什么的

材料规划工具的网页（`index.html`）要显示角色、材料、突破需求、关卡掉落等信息。
这些信息**来自一张 Excel 统计表**，但浏览器读不了 Excel，只能读 `game-data.js`。

**这个转换脚本就干一件事：**

```
Excel 表格  ──转换脚本──▶  game-data.js  ──▶  网页工具显示
```

每次表格更新，你重新跑一次脚本，`game-data.js` 就自动更新了。
网页刷新后，就显示新数据了。

**核心特点：**

- 自动从 `excel/` 目录里挑日期最新的表格，不用手动指定
- 转换前自动备份旧的 `game-data.js`，想回滚随时回
- 每次生成两个报告（转换检查 + 新旧差异），改了什么一目了然
- 报告名带日期和时分，同一天跑多次也不会互相覆盖

## 三、关于 .gitignore

仓库根目录会有一个 `.gitignore` 文件，它的作用是：**告诉 Git 哪些文件不要上传到 GitHub。**

### 为什么需要它

跑脚本会生成一些**本地产物**，比如：

- `data tool/node_modules/` —— 依赖包，几十 MB
- `data tool/reports/` —— 报告文件，每次跑都新增
- `data tool/backup/` —— 数据备份，每次跑都新增
- `*.bak` —— 手动备份的旧文件

这些文件**没必要上传 GitHub**：

- 体积大，仓库会越来越臃肿
- 别人 clone 后也用不到（自己跑脚本重新生成就行）
- GitHub 本身已经有每次 commit 的历史，相当于另一种备份

### `.gitignore` 长什么样

打开仓库根目录的 `.gitignore`，应该包含下面这些内容：

```gitignore
# 依赖包
node_modules/

# 本地报告和备份
data tool/reports/
data tool/backup/

# 手动备份
*.bak

# Excel 打开时产生的临时文件
~$*.xlsx

# 系统文件
.DS_Store
Thumbs.db
```

### 每一行的含义

| 规则                 | 忽略什么                             |
| -------------------- | ------------------------------------ |
| `node_modules/`      | 所有 `node_modules` 目录（不限位置） |
| `data tool/reports/` | 工具目录下的报告文件夹               |
| `data tool/backup/`  | 工具目录下的备份文件夹               |
| `*.bak`              | 所有 `.bak` 结尾的文件               |
| `~$*.xlsx`           | Excel 打开时产生的隐藏临时文件       |
| `.DS_Store`          | macOS 系统生成的垃圾文件             |
| `Thumbs.db`          | Windows 系统生成的缩略图缓存         |

### 常见问题

**Q：`data tool/` 里有空格，`.gitignore` 里要加引号吗？**
不用。直接写 `data tool/backup/` 就行，Git 认得。

**Q：`node_modules/` 前面要不要加 `data tool/`？**
不用。`node_modules/` 这一条会**匹配任意位置**的同名文件夹。如果只想忽略工具目录下的，可以写 `data tool/node_modules/`。

**Q：怎么确认 `.gitignore` 生效了？**
在仓库根目录跑：
```bash
git status
```
如果 `reports/`、`backup/`、`node_modules/` **没有出现在 "Untracked files" 列表里**，就说明生效了。

**Q：如果某个文件已经被 Git 跟踪了（之前提交过），`.gitignore` 还能忽略它吗？**
不能。`.gitignore` 只对**未跟踪**的文件生效。如果之前已经提交过，得先：
```bash
git rm -r --cached "data tool/backup"
```
（这行命令**只让 Git 不再跟踪它，本地文件不会删**）
然后再 `git status` 就不显示了。

**Q：`.gitignore` 本身要不要上传？**
**要。** 它是个普通配置文件，必须提交到 GitHub。别人 clone 后也能享受同样的忽略规则。

**Q：`.gitignore` 里写路径用正斜杠 `/` 还是反斜杠 `\`？**
**正斜杠 `/`**。Git 统一用正斜杠，即使在 Windows 上也是。

**Q：想临时把某个被忽略的文件传上去怎么办？**
用 `git add -f 文件路径` 强制添加，`-f` 表示 force。**不推荐**，除非有明确理由。

**Q：怎么全局忽略（所有仓库都生效）？**
```bash
git config --global core.excludesfile ~/.gitignore_global
```
然后编辑 `~/.gitignore_global`，写入规则。
**但一般不建议全局忽略，容易造成不同仓库行为不一致。**

## 四、第一次准备（只做一次）

### 4.1 装 Node.js

Node.js 是运行脚本必须的软件。

1. 打开 <https://nodejs.org>
2. 下载 **LTS（长期支持）版**，一路点「下一步」装完
3. 验证是否装好：
   - Windows：打开 **CMD** 或 **Git Bash**
   - Mac：打开 **终端**
   - 输入：`node -v`
   - 如果显示 `v20.x.x` 或更高 → 装好了

### 4.2 在 `data tool/` 里装依赖

1. 在 `data tool/` 文件夹里右键 → 「Git Bash Here」（或「在终端中打开」）
2. 输入：
   ```bash
   npm install xlsx
   ```
3. 看到 `added X packages in Xs` → 成功

**如果下载很慢，换国内镜像：**
```bash
npm install xlsx --registry=https://registry.npmmirror.com
```

装完后 `data tool/` 里会多出 `node_modules/` 文件夹和两个 `package*.json` 文件。

### 4.3 确认 `excel/` 里有表格

表格文件名必须**以 8 位日期结尾**：

| 文件名                                       | 能不能被识别                               |
| -------------------------------------------- | ------------------------------------------ |
| `刀剑乱舞ばずき统计ver0.2-20261001.xlsx`     | ✅                                          |
| `刀剑乱舞ばずき统计ver3.2-20261001.xlsx`     | ✅                                          |
| `刀剑乱舞ばずき统计ver3.2-2026-10-01.xlsx`   | ✅                                          |
| `刀剑乱舞ばずき统计ver0.2-20261001 .xlsx`    | ❌ 末尾有空格                               |
| `刀剑乱舞ばずき统计ver0.2-20261001测试.xlsx` | ❌ 日期不在末尾                             |
| `刀剑乱舞ばずき统计ver0.2测试-20261001.xlsx` | ⚠️ 日期在末尾，但如果混入全角连字符可能失败 |

**命名黄金规则：日期放最后 8 位，后面直接跟 `.xlsx`，中间别加空格、全角字符。**

## 五、每次更新表格的完整流程

### 步骤 1：把新表格丢进 `excel/`

按规则命名，例如：
```
刀剑乱舞ばずき统计ver0.2-20261005.xlsx
```
**旧版表格不用删**，脚本会自动挑日期最新的。

### 步骤 2：跑脚本

打开 `data tool/` 里的终端，输入：

```bash
node convert-pazugiri.js
```

**你会看到类似这样的输出：**
```
📊 自动选择最新表格：刀剑乱舞ばずき统计ver0.2-20261005.xlsx
📅 报告日期前缀：2026-10-05_1042
📦 已备份旧数据到：backup/2026-10-05_1042_game-data.js
转换完成 ✅
  刀男 42 把 · 突破阶段 141 条 · 材料 63 个
  配方 85 条（27 个成品）· 关卡 36 关
  警告 3 条（请打开 convert-report.md 查看！）
  ✅已生成新旧差异报告：2026-10-05_1042_update-diff-report.md
输出文件：../game-data.js / 2026-10-05_1042_convert-report.md / 2026-10-05_1042_update-diff-report.md
```

**看到 `转换完成 ✅` 就算成功。**

### 步骤 3：看两个报告

打开 `data tool/reports/` 目录，会看到两份新的报告：

- `2026-10-05_1042_convert-report.md` —— 转换检查报告
- `2026-10-05_1042_update-diff-report.md` —— 新旧差异报告

**看报告的顺序和重点：**

**先看 `convert-report.md`（转换检查报告）** —— 确认脚本这次没出问题

- 翻到 **「二、⚠ 警告清单」**
  - 有没有「未映射」的材料？→ 表格里可能有拼错的名字
  - 有没有「词典冲突」？→ 一个日文名对多个中文名，要人工确认
  - 有没有「跳过的行」？→ 表格里有空行或异常行

- 翻到 **「一、转换概览」**
  - 刀男角色数、突破阶段数、材料数、关卡数是否合理
  - 关卡数对比上次是不是变化太大

**再看 `update-diff-report.md`（新旧差异报告）** —— 确认这次表格改了什么

- 顶部「📊 总量总览」：一眼看各项目增减
- 第 1 节 角色、第 2 节 材料、第 3 节 突破阶段
- 第 4 节 配方、第 5 节 关卡、第 6 节 小判
- 逐条核对是不是表格的真实改动，有没有异常

**如果两个报告都正常** → 数据没问题，可以 push。

### 步骤 4：push 到 GitHub

```bash
cd ..                          # 回到仓库根目录
git add .
git commit -m "更新数据到 2026-10-05"
git push
```

**GitHub Pages 会自动更新，几分钟后网页就显示新数据。**

## 六、两个报告怎么看

### 6.1 `convert-report.md`（转换检查报告）

**这是"脚本自己觉得有没有问题"的报告。**

| 章节               | 看什么                                                |
| ------------------ | ----------------------------------------------------- |
| **转换文件**       | 确认用的是哪张表格                                    |
| **转换时间**       | 表格的日期（不是脚本运行日期）                        |
| **一、转换概览**   | 各数据的总数，跟上次对比是否合理                      |
| **材料中日对照表** | 每个材料的日文名、中文名、类型、小判花费              |
| **小判消耗清单**   | 合成物需要多少小判                                    |
| **关卡掉落清单**   | 每个关卡掉哪些材料                                    |
| **二、⚠ 警告清单** | **重点！** 所有异常都会列在这里                       |
| **别名归一化**     | 表格里用了日文名/别名，被自动纠正的（无别名时不显示） |
| **需求为空的阶段** | 表格里没填材料需求的突破段                            |
| **跳过的行**       | 脚本认为无效而跳过的行                                |
| **三、人工检查点** | 建议你一条条确认的 checklist                          |

### 6.2 `update-diff-report.md`（新旧差异报告）

**这是"这次表格相比上一次改了啥"的报告。**

结构：

```
📊 总量总览           ← 表格形式：旧数量 / 新数量 / 净变化
1. 角色 characters    ← 新增、删除
2. 材料 materials     ← 新增、删除、属性变化
3. 突破阶段           ← 整条阶段增删、阶段内部需求变化
4. 合成配方 recipes   ← 配方增删、配料数量变化
5. 关卡 stages        ← 关卡增删、掉落材料变化
6. 小判花费 coinCosts ← 数值变化
```

**重点看：**
- 净变化特别大的项目（比如关卡少了 10 个）→ 可能是表格误删，回去核对
- 「需求为空的阶段」变多了 → 表格有数据没填
- 「删除角色/材料」→ 确认是不是真的删了

### 6.3 如果同一天跑了两次

`reports/` 里会有两组报告，时间不同：

```
2026-10-05_1042_convert-report.md
2026-10-05_1042_update-diff-report.md
2026-10-05_1530_convert-report.md
2026-10-05_1530_update-diff-report.md
```

- 第一次跑的差异：**原始 → 第一次改动**
- 第二次跑的差异：**第一次改动 → 第二次改动**

**两份都保留，写更新日志时可以对着看。**

## 七、报告命名规则与文件命名规则

### 7.1 报告命名规则

```
reports/YYYY-MM-DD_HHMM_convert-report.md
reports/YYYY-MM-DD_HHMM_update-diff-report.md
```

- `YYYY-MM-DD` = **表格文件的日期**（不是脚本运行日期）
- `HHMM` = **脚本运行的时分**

**例子：**
- 表格是 `...-20261001.xlsx`
- 你 10 月 5 号 15:30 跑
- 报告名 → `2026-10-01_1530_convert-report.md`

**为什么日期用表格的？** 因为这份数据描述的"游戏内容"是那一天的状态，不是脚本跑的时间。

### 7.2 Excel 表格命名规则

**推荐：**
```
刀剑乱舞ばずき统计verX.X-YYYYMMDD.xlsx
```

- `X.X` = 版本号，随便涨
- `-` = **ASCII 半角连字符**（键盘上 0 和 = 中间那个）
- `YYYYMMDD` = 8 位日期，**放末尾**
- 后面直接跟 `.xlsx`，**不加空格、不加任何字**

**不要：**
- ❌ `...-20261001测试.xlsx`（测试二字在日期后）
- ❌ `...-20261001 .xlsx`（空格）
- ❌ `...20261001.xlsx`（没有连字符也行，但如果后面还有字符可能出问题）
- ❌ 日期在中间，比如 `...-20261001-最终版.xlsx`

## 八、回滚到上一版数据

**场景**：跑完发现这次的数据不对，或者网页显示有问题，想回到上次的数据。

### 方法 1：从 `backup/` 恢复

1. 打开 `data tool/backup/`
2. 找想要的那份（一般是最近一次之外的），例如 `2026-09-30_1438_game-data.js`
3. 复制出来，改名覆盖根目录的 `game-data.js`
4. 刷新网页

**`backup/` 里每次转换都留一份：**
- `backup/2026-09-30_1438_game-data.js` = 2026-09-30_1438 这次转换**之前**的旧数据
- `backup/2026-10-01_1042_game-data.js` = 2026-10-01_1042 这次转换**之前**的旧数据

### 方法 2：从 git 历史恢复

如果你已经 push 过：
1. 上 GitHub 打开 `game-data.js`
2. 点右上角 **History**
3. 找到任意一次提交，点开
4. 右侧有 **Raw** / **Download** 按钮，直接拿回那一版

**说明**：`backup/` 和 `reports/` 都不会上传 GitHub（`.gitignore` 已忽略），所以从 git 历史里恢复只能拿回 `game-data.js` 本身，拿不回报告。

**`backup/` + git 历史 = 双保险。**

## 九、自动选表格的原理

脚本会：

1. 扫描 `excel/` 目录里所有 `.xlsx`（排除 `~$` 开头的临时文件）
2. 从每个文件名里**提取末尾 8 位日期**
3. 按日期排序，选**日期最大**的那个

**关键点：日期必须在末尾，8 位纯数字。**

**如果你不想自动选**，可以手动指定：

打开 `convert-pazugiri.js`，找到：

```javascript
autoSelectLatest: true,
excelFileName: "刀剑乱舞ばずき统计ver0.2-20260930.xlsx",
```

改成：

```javascript
autoSelectLatest: false,
excelFileName: "刀剑乱舞ばずき统计ver0.2-20260930.xlsx",  // 想用哪张就写哪张
```

这样脚本就只读指定的那张表格。

## 十、表头 / 表名 / 文件名变动怎么办

脚本顶部有 **CONFIG 配置区**，所有可调的东西都在这：

```javascript
const CONFIG = {
  /* Excel 目录 */
  excelDir: path.join(rootDir, "excel"),

  /* 是否自动选最新表格 */
  autoSelectLatest: true,
  excelFileName: "刀剑乱舞ばずき统计ver0.2-20260930.xlsx",

  /* 四张工作表名字 */
  sheetNames: {
    chars: "刀男所需材料",
    recipes: "材料合成",
    sources: "材料来源",
    stages: "关卡统计",
  },

  /* 各表表头文字 */
  headerTexts: { ... },

  /* 货币名 */
  coinName: "小判",

  /* 旧数据、新数据、报告路径 */
  oldGameDataFile: path.join(rootDir, "game-data.js"),
  outputJs: path.join(rootDir, "game-data.js"),
  reportDir: path.join(__dirname, "reports"),
  outputReport: "",
  diffReport: "",
};
```

**要改什么就改对应那行：**

| 你遇到的情况       | 改哪                                                             |
| ------------------ | ---------------------------------------------------------------- |
| 想固定用某张表格   | `autoSelectLatest` 改 `false`，`excelFileName` 写文件名          |
| Excel 目录换了位置 | `excelDir`                                                       |
| 工作表名字改了     | `sheetNames`（带后缀会自动前缀匹配，如「关卡统计（透视表用）」） |
| 表头文字改了       | `headerTexts`                                                    |
| 货币不叫小判了     | `coinName`                                                       |
| 想换报告输出目录   | `reportDir`                                                      |

**新增角色 / 材料 / 关卡 / 配方 / 突破阶段**：只要表头没变，脚本自动识别，**不用改任何代码**。

## 十一、四张工作表各管什么

| 工作表名         | 转换后对应什么                                                         | 关键列                         |
| ---------------- | ---------------------------------------------------------------------- | ------------------------------ |
| **刀男所需材料** | 角色列表、普/彩稀有度、突破阶段（10→20 / 20→30 / 30→35）和每段材料需求 | 类型、刀刀、稀有度、进阶、材料 |

**其他工作表**（如「其他工具」「留言」）：忽略，脚本不处理。

## 十二、转换规则详解

### 12.1 材料显示规则

- 中日文一致 → 只显示一个（`水` 就显示 `水`）
- 中日文不一致 → 显示 `日文|中文`（`丸太|木材`）

### 12.2 小判（游戏货币）

- **不占背包、不进材料缺口**
- 单独记录在 `coinCosts`
- 合成页会显示「合成需 小判 × N」

### 12.3 合成物

- 下拉里只列**能合成的材料**（如茶碗、围棋、花札）
- 选一个 → 显示拆到基础材料各要几个
- 支持多层递归（茶碗 → 碗 → 粘土 + 打火石）

### 12.4 突破筛选

**规则：只算「起点 ≥ 当前上限」且「终点 ≤ 目标等级」的段。**

例子：当前上限 5，目标 35
- 算：10→20、20→30、30→35 三段 ✅
- 不算：5→10（起点 5 不 ≥ 5）

例子：当前上限正好 30，目标 35
- 算：30→35 一段 ✅
- 不算：10→20、20→30（终点 ≤ 30，但起点 < 30）

### 12.5 普 / 彩稀有度

以下 5 把刀有普/彩两套数据，选到时会让你选稀有度：
- 太郎太刀
- 三日月宗近
- 一期一振
- 歌仙兼定
- 乱藤四郎

其他刀只有普。

### 12.6 别名归一化

同一种材料的不同写法会被自动统一：

- `丸太` → `木材`
- `桃` → `桃子`
- 其他日文名 → 对应中文名

**归一的依据是表格里「材料来源」工作表的「中文名 ↔ 日文名」对照。**

如果转换时有归一化，`convert-report.md` 里会有 **「别名归一化」** 一节；
**如果没有任何别名，这一节不会出现。**

### 12.7 数据容错

- 表格里空白的阶段 → 按 0 需求处理，报告里会列出
- 表里拼错的材料名 → 会在「未映射」警告里列出
- 表里重复的关卡 → 保留第一条，其余跳过并列入报告

## 十三、常见问题 FAQ

### Q1：第一次跑脚本，没生成差异报告？

**正常。** 第一次跑的时候没有旧 `game-data.js` 可对比，脚本会提示"跳过差异报告"。从第二次开始就有了。

### Q2：脚本自动选的表格不对？

**检查两件事：**

1. `excel/` 里所有 `.xlsx` 的**末尾 8 位日期**是不是最大那个
2. 文件名末尾**有没有空格**、**有没有额外字符**

如果拿不准，改 `autoSelectLatest: false`，手动指定 `excelFileName`。

### Q3：跑完 `game-data.js` 里 `generatedAt` 不对？

说明表格文件名没被正确解析。

- 检查文件名末尾日期前后有没有空格、特殊字符
- 打开终端，看 `📅 报告日期前缀` 是不是你想要的那个

### Q4：报告里为什么没有「别名归一化」这一节？

**说明表格里没有别名需要转换。** 所有材料名都是标准中文名，脚本认为不需要报。这是好事。

### Q5：报告里同一天有两份怎么办？

**正常。** 时分不同，两次都保留：

- 第一次跑的差异：**原始 → 第一次改动**
- 第二次跑的差异：**第一次改动 → 第二次改动**

写更新日志时可以对着两份看。

### Q6：`reports/` 里的旧报告可以删吗？

**可以，手动删。** 脚本不会自己删。建议保留最近几次，历史太久的手动清理。

### Q7：`backup/` 里的备份可以删吗？

**可以，但建议留几份。** 万一想回滚，最近几次的备份最有用。历史太久的可删。

### Q8：跑完网页没更新？

**大概率是浏览器缓存。** 按 `Ctrl + F5`（Mac：`Cmd + Shift + R`）强制刷新。

还不行的话，检查：

- `game-data.js` 是不是真的更新了（打开看 `generatedAt`）
- `index.html` 是不是同一目录下的
- F12 看控制台有没有报错

### Q9：工具算出来的数字不对？

**按顺序检查：**

1. `convert-report.md` 的「警告清单」有没有异常
2. 表格里对应那一行数据是不是真的
3. 浏览器 F12 看 Console 有没有报错

### Q10：表格里有新的角色/材料/关卡，要改代码吗？

**不用。** 只要表头没变，脚本自动识别新增内容。

### Q11：换电脑了怎么办？

**两种情况：**

**有 `node_modules/` 备份：**
- 把整个 `touken-puzzle-tool/` 文件夹带走

**没有 `node_modules/`：**
- 拷贝所有源文件（`.js`、`.html`、`.css`、`.md`、`excel/`）
- 在新电脑的 `data tool/` 里跑一次 `npm install xlsx`

**工具里的计划和背包数据**：在浏览器本地（localStorage），用工具首页的「导出备份 / 导入备份」迁移。

### Q12：`node_modules/` 要不要上传 GitHub？

**不要。** 它体积大（几十 MB），已经在 `.gitignore` 里忽略了。GitHub 上只需要 `package.json` 和 `package-lock.json`，别人 clone 后自己跑 `npm install xlsx` 就行。

**为什么不上传？**

- 体积太大，clone 慢
- 不同系统的 `node_modules` 不通用（Mac 装的和 Windows 装的不一样）
- 有了 `package.json`，随时能重装

### Q13：`reports/` 和 `backup/` 要不要上传 GitHub？

**不上传。** 它们是本地产物，已经 `.gitignore`。

**为什么不上传？**

- 每次跑脚本都新增，越积越多
- GitHub 历史里已经有每次的 `game-data.js`，等于有备份
- 报告只是给你自己看的，不用分享

### Q14：我一天跑了好几次脚本，会不会覆盖？

**不会。** 报告名带时分，跑几次就有几份。备份也是。

### Q15：`npm install xlsx` 报错？

**常见原因：**

- 网络问题 → 换国内镜像：`npm install xlsx --registry=https://registry.npmmirror.com`
- Node.js 版本太老 → 升级到 LTS 版
- 权限问题 → 用管理员/root 权限再跑

### Q16：终端里中文乱码？

在 Git Bash 里跑：

```bash
git config --global core.quotepath false
```

之后中文文件名就能正常显示了。

### Q17：怎么确认用的表格是最新的？

看脚本第一行输出：

```
📊 自动选择最新表格：xxx.xlsx
```

如果不对，打开 `excel/` 目录，检查所有表格的末尾日期，删掉/改名不需要的旧表格。

### Q18：跑脚本前需要备份 `game-data.js` 吗？

**不需要。** 脚本每次转换前会**自动**备份到 `backup/` 里。

### Q19：脚本运行时能不能中途关闭？

**不建议。** 运行中关闭可能导致 `game-data.js` 写到一半，数据损坏。等它跑完（看到 `转换完成 ✅`）再关。

### Q20：为什么要有「需求为空的阶段」？

表格里有些突破段还没填材料需求（比如 30→35 段的某些刀），脚本会按 0 处理并在报告里列出，提醒你或表格维护者补填。
